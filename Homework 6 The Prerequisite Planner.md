### Part A: DFS Timestamps & Ordering (50 Points)

**Instructions:** Answer Questions 1–4 in a separate PDF or Markdown document, using matching numbers. Review slides 54–62 and the worked trace on slide 61.

1. **Why DFS, Not BFS, For This Job:**

A **topological order** places each vertex before every destination of its outgoing edges. A DFS-based algorithm constructs such an order on a DAG using each vertex's **finish time**, when its recursive call returns. Explain in one or two sentences why BFS, which processes nodes level-by-level rather than one deep path at a time, doesn't naturally produce finish times the same way DFS does.

2. **Visual Tracing — DFS Discovery/Finish Times:**

Given the prerequisite graph with directed edges CS115 -> CS215, CS115 -> CS258, CS215 -> CS311, CS258 -> CS311, CS311 -> CS411 (an edge A -> B means "A is a prerequisite for B"), trace a DFS starting from CS115 (visiting outgoing edges in alphabetical order of the destination course). Record the **discovery time** and **finish time** of every vertex, using a single incrementing clock across the whole traversal.

3. **From Finish Times to Topological Order:**

State the rule that converts a set of DFS finish times into a valid topological order, and apply it to your Question 2 trace to produce the final course registration order.

4. **Cycle Detection via Edge Classification:**

During a DFS, an edge from the current vertex to an **ancestor still on the current recursion stack** is called a "back edge," and its presence means the graph has a cycle. Explain how you can detect a back edge during the traversal using only the information you already have at each recursive call (hint: track which vertices are on the current path, not just which have been visited overall) — and explain why a plain "already visited" check by itself is not enough to distinguish a back edge from a perfectly normal DAG edge that happens to point to an earlier-visited vertex.
